# 折痕历史、对齐与纸飞机整理（2026-11-04）

本文件为初轮记录；后续已完成完整浏览器纸飞机流程验收并继续修复问题，当前结论与限制见 [完整验收记录](AIRPLANE_ACCEPTANCE_2026-11-04.md)。

## 本轮判断

原自由折叠模型只保留一个 Turn；新增折线会覆盖可操作折轴，因此撤销以外无法访问早期折痕。松手后的角度条仅控制最后一折，且接近 180° 会强制压平。吸附只覆盖顶点和中点，没有可见反馈，不能帮助边到边定位。

## 改动

- 保留每次折叠的材料区域、参考纸面、折轴与折角（最多 64 条）。折痕下拉选择器支持回选早期折痕，沿原轴展开和微调折角。
- 用最终材料拓扑重放各折痕；后续折轴随参考纸面变换。调整后检查共享材料位置（含 T 接点），若纸面连接不相容，原子拒绝，保留原纸形。全部展开同时把记录折角归零，可绕开需要协调展开的交叉约束。
- 全部展开保留折痕，可恢复本次展开前纸形。恢复快照只保留在本次页面会话中；导出/刷新保存的是当前纸形及全部折痕记录。
- 显示历史折痕及选中高亮，虚线包括被纸层遮挡的部分，属于辅助透视叠层。
- 吸附到顶点、边中点、边缘及折痕分界，提供绿色标记和文字；吸附范围按 CSS 像素计算。
- 数字输入支持 0.5° 步长及 ±1° 按钮；精确操作不再把 179° 或 0.5° 强制吸到压平/展开状态。
- finish 幂等，重复整理同一折不再增加折叠次数。新记录随纸形导出/导入与本地保存。

## 验证与范围

- `npm run typecheck` 通过。
- `npm test`：25 项通过。纸飞机用无预置折线的 8 次输入生成：中线预折/展开、两次鼻角、两次收窄、机身合折、两侧机翼。完成第二翼后，回选第一翼到 -93.6°、第二翼到 86.4°，检查材料面积与每条纸边长度；全部展开返回原材料坐标，保留折痕，再保存/恢复立体纸形。
- 交叉折痕的不相容调整拒绝且存档完全不变；旧存档读取与最近折角调整通过。
- Cocos Creator 3.8.8 Web 导出通过，`npm run test:web-bundle` 通过，覆盖实际编译后的控制器拖角、撤销、取消，以及历史折角微调、展开、折痕线段和保存恢复。
- Chrome 实际 UI：白纸连续拖两个鼻角；选择第一条折痕并按 −1° 得到 179°；全部展开可见两条折痕；刷新后记录和当前纸形保留。截图位于忽略目录 `artifacts/screenshots/crease-history-2026-11-04.png`。
- 本地生成的 8 折飞机样本：`artifacts/examples/airplane-adjustable.foldpaper`（忽略目录）。尝试通过浏览器导入该样本受 Chrome 扩展本地文件访问权限限制，未完成浏览器中完整飞机的视觉验收；没有更改用户扩展权限。
- 本机缺 Emscripten，`scripts/package-web.mjs` 因缺少旧物理内核 Wasm 无法完成完整打包。自由折叠不依赖此内核：本地预览使用已导出的 Cocos 资源并复制工作台 CSS；本轮没有验证 `?physics`。

## 尚未解决

本轮调整的是沿原折轴的二面角，没有增加折后平移/旋转折线位置的功能。修改折线位置仍需展开相关折叠后重新压线。任意交叉折痕的联动求解、碰撞/厚度、材料回弹和真实飞机手感尚未完成。旧存档没有早期历史，能保留旧纸形与最后一折，不能推断恢复已丢失步骤；“全部展开”对旧存档只能展开其已有记录。
